Academic Research Report · Version 1.0

Explainable Four-Class Brain MRI Classification with VGG16 Transfer Learning and Grad-CAM

NeuroScan AI: system design, held-out evaluation, and responsible-use analysis

Project: NeuroScan AI Date: 1 November 2026 Artifact version: 1.2.0 Evaluation: 1,600 held-out images

Abstract

This report describes NeuroScan AI, an end-to-end research prototype for four-class brain MRI slice classification. The system couples an existing VGG16 transfer-learning model with genuine gradient-weighted class activation mapping (Grad-CAM), a Flask inference API, a SQLite patient and scan store, and self-contained HTML reports. The deployed network receives a 128 × 128 RGB slice, uses an ImageNet-pretrained VGG16 backbone with block5 fine-tuned, and ends in a compact classifier head: Flatten, Dropout(0.30), Dense(128, ReLU), Dropout(0.20), and a four-way softmax. We evaluated the saved weights on all 1,600 images in the held-out test split, with no sampling or threshold tuning. Overall accuracy was 90.94% (1,455/1,600), with macro precision 92.00%, macro recall 90.94%, and macro F1 90.64%. The aggregate result conceals an important failure mode: glioma recall was only 69.25%, and 97 of the 123 missed gliomas were predicted as meningioma. The report argues that per-class sensitivity, not accuracy alone, must govern how such a prototype is presented. Grad-CAM is treated as model-attention evidence, not as a lesion boundary or radiological finding. The system is an academic prototype, not a medical device, and has not been externally validated or clinically tested.

Keywords: brain MRI; VGG16; transfer learning; Grad-CAM; explainable artificial intelligence; Flask; SQLite; medical image classification

1Introduction

Brain MRI is a routine part of neuro-oncology assessment, but image interpretation is time-consuming, observer-dependent, and constrained by specialist availability. A machine-learning system that ranks a small set of common appearances could support triage, teaching, or retrospective audit. It cannot, however, substitute for a radiologist, a volumetric study, or clinical context. This distinction frames the present work.

NeuroScan AI is an academic prototype that classifies a single MRI slice into one of four categories: glioma, meningioma, no tumor, and pituitary tumor. The project had two goals. The first was engineering: preserve an existing trained VGG16 artifact and expose it through a reproducible application with real inference, real persistence, real reports, and inspectable explanations. The second was evidentiary: evaluate the deployed weights on the complete held-out split and report the result honestly, including the class that performs poorly.

The contribution is therefore not a new architecture or a claim of clinical novelty. It is a documented system that connects a transfer-learning classifier to genuine Grad-CAM, stores the resulting evidence against patient and scan identifiers, and produces a report that separates what the model output says from what a clinician might conclude. The report also records the limits of that evidence: a single internal test split, no external validation, no calibration study, and no reader study.

2Background and Related Work

VGG16 is a deep convolutional network introduced by Simonyan and Zisserman, built from repeated 3 × 3 convolutions and max-pooling stages followed by fully connected layers [1]. Its uniform convolutional design makes it a useful transfer-learning backbone: early and middle layers learn generic edge, texture, and shape features, while later layers can be adapted to a new label space. Transfer learning is attractive when the target dataset is much smaller than the source dataset, because low- and mid-level filters need not be learned from scratch [2].

Explainability is a separate problem. Grad-CAM computes the gradient of a target class score with respect to the feature maps of a chosen convolutional layer, global-average-pools those gradients into channel weights, and combines the feature maps into a coarse localization map [3]. The result shows where the network's evidence for a class is concentrated. It does not segment a lesion, establish a boundary, or prove causality. A heatmap can look plausible while the prediction is wrong, which is why the interface and report describe Grad-CAM as model attention rather than radiological evidence.

Much of the medical-imaging literature reports aggregate accuracy on a single split. That practice can hide clinically consequential asymmetries. In a four-class problem, a model may achieve high accuracy by performing well on the majority or easiest classes while missing a large fraction of one tumor type. This report therefore reports the full confusion matrix and per-class sensitivity alongside the aggregate score.

3Materials and Methods

3.1 Dataset

The project dataset is balanced across four classes. The training split contains 5,600 images and the test split contains 1,600 images, with 1,400 training and 400 test images per class. All 1,600 test images were used in the evaluation; no image was excluded, subsampled, or reweighted after the fact.

3.2 Preprocessing

Inference preprocessing is deliberately simple and is implemented in one place, ml_model.preprocess_pil. Each image is converted to RGB, resized to 128 × 128 with bilinear interpolation, converted to float32, divided by 255 to map pixel values to [0, 1], and expanded to a batch dimension. No ImageNet mean/std normalization is applied by the deployed inference path. The evaluation script reproduces the same steps so that test-time preprocessing matches application behavior.

3.3 Model architecture

The saved Keras artifact contains an ImageNet-pretrained VGG16 backbone with block5 convolutional layers fine-tuned and earlier blocks frozen. The classifier head is intentionally small. A Flatten layer converts the 4 × 4 × 512 backbone output into 8,192 features; Dropout(0.30) precedes a 128-unit ReLU layer; Dropout(0.20) precedes the final four-unit softmax. The saved configuration compiles the model with sparse categorical cross-entropy and sparse categorical accuracy. Class index order is fixed as glioma, meningioma, notumor, pituitary, and must not be changed without retraining.

3.4 Training configuration and artifact scope

The deployed artifact records the compiled loss, metric, and layer configuration. Optimizer settings, epoch count, and the exact fine-tuning schedule are not stored in the saved model files, so this report does not invent them. The evaluation below concerns the saved weights and their behavior on the held-out split, not a reproduction of the original training run. That distinction matters: the reported metrics are a property of the artifact that serves predictions, not of an idealized training notebook.

3.5 Grad-CAM

For a predicted class c, the implementation captures feature maps Ak from block5_conv3, computes the gradient of the class score with respect to those maps, global-average-pools the gradients into channel weights, forms a weighted sum, applies ReLU, and normalizes by the maximum activation. The activation map is resized to the original image dimensions and rendered with a Jet colormap. Two outputs are retained: the raw heatmap and a 55% original / 45% heatmap overlay. They are different images and both are persisted.

3.6 Application implementation

The Flask API validates uploads, looks up or registers a patient, runs inference, computes Grad-CAM, persists the scan and report, and returns the original image, raw heatmap, overlay, four probabilities, identifiers, and report links. SQLite stores patients, scans, and reports with foreign keys and additive, idempotent migrations. Reports embed patient/scan/report identifiers, all images, all four probabilities, model facts, a model-output-only summary, and a disclaimer. The frontend is a static HTML/CSS/JavaScript application with a dark navy, cyan, turquoise, purple, and emerald visual system. Motion is confined to the marketing page; MRI and Grad-CAM images are never animated, and reduced-motion preferences are honored.

3.7 Evaluation protocol

Evaluation used the saved weights and the full test split. Each image was resized with bilinear interpolation to 128 × 128, scaled to [0, 1], and passed through the network in batches of 64. The predicted class was the argmax of the four softmax outputs. Accuracy, per-class precision, recall, F1, and the confusion matrix were computed from the resulting 1,600 predictions. CPU inference took 355.27 seconds in total, approximately 222 ms per image, including preprocessing and batch overhead. No test-time augmentation, threshold tuning, or post-hoc class reweighting was used.

4.2 Class-level sensitivity

No-tumor and pituitary classes performed strongly, with recall of 99.25% and 98.75% respectively. Meningioma recall was also high at 96.50%, but its precision fell to 78.94% because the class absorbed a large number of glioma errors. Glioma precision was high at 97.54%, yet recall was only 69.25%. In other words, when the model predicted glioma it was usually right, but it missed almost one in three gliomas.

4.3 Confusion matrix and error structure

The confusion matrix makes the failure mode explicit. Of 400 gliomas, 277 were classified correctly, 97 were classified as meningioma, 18 as no tumor, and 8 as pituitary. The 97 glioma-to-meningioma errors are the single largest off-diagonal block and explain why meningioma precision is depressed while glioma recall is low. The no-tumor and pituitary rows are comparatively clean, with only three and five errors respectively.

Primary failure mode

Glioma sensitivity is 69.25%. The model missed 123 of 400 gliomas, and 97 of those errors were routed to meningioma. High overall accuracy and high glioma precision do not offset this result. For any hypothetical screening use, a missed glioma would be the most consequential error pattern in this evaluation.

4.4 Deployment verification

The report distinguishes model performance from application correctness. The deployed system was exercised with isolated SQLite databases and a real held-out image. Integration checks covered health, patient registration, prediction, Grad-CAM persistence, report endpoints, validation failures, and service metadata. A browser audit drove the real upload flow and checked the rendered original MRI, raw heatmap, overlay, four probabilities, report actions, history, console errors, and failed requests. A separate layout audit covered four viewports and reduced-motion behavior, and a generated-report audit checked the real backend-rendered report at desktop and mobile widths plus print media. Production compatibility was tested on a byte-for-byte copy of the existing database; the original file hash was unchanged.

5Discussion

5.1 What the results support

The results support a narrow claim: the saved VGG16 artifact can classify this four-class, single-slice test split with 90.94% accuracy, and its behavior is stable enough to be served through a real application. The no-tumor and pituitary classes are strong on this split, and meningioma recall is high. The engineering path also works end to end: a user can upload an image, receive four probabilities, inspect a genuine Grad-CAM heatmap and overlay, and open a report containing the same evidence.

The results do not support a claim of clinical readiness. Glioma recall of 69.25% is a material weakness, and the confusion matrix shows that the model systematically routes many gliomas toward meningioma. Aggregate accuracy is a poor summary of that behavior. A clinician reviewing the system would need to know not only that it is usually right, but also which class it tends to miss and where those misses go.

5.2 Why Grad-CAM is presented carefully

Grad-CAM adds inspectability, but it can also create false confidence. A heatmap that highlights a plausible region does not prove that the region is pathological, that the prediction is correct, or that the model used a clinically meaningful feature. The application therefore returns both the raw heatmap and the overlay, labels them as model attention, and states that Grad-CAM is not segmentation. The report summary is generated from model output only: it names the highest-probability class, gives the probability, lists the ranking, and notes that the output is statistical. It does not invent anatomical findings, measurements, staging, or recommendations.

5.3 Limitations and responsible use

The evaluation is internal to one project dataset. There is no external, multi-site, prospective, or reader-study validation. The model sees one 128 × 128 slice and loses volumetric and acquisition context. Only four classes are represented, so other tumors, infections, artefacts, and normal variants are outside the label space. Softmax probabilities are not calibrated, and no subgroup analysis by age, sex, scanner, or site was performed. The application is a prototype: it has no authentication, authorization, audit logging, encryption at rest, or regulatory clearance. The SQLite database contains identifiable data and must not be exposed to untrusted networks.

Responsible-use statement

NeuroScan AI is an academic research prototype. Its output is a statistical classification, not a diagnosis or radiological finding. “No Tumor Detected by AI Model” does not rule out disease. Clinical decisions require a qualified radiologist or physician. The software is not a certified medical device and must not be used for patient care.

6Conclusion

This report documented a complete VGG16 + Grad-CAM + Flask + SQLite prototype and evaluated the saved weights on all 1,600 held-out images. The system achieved 90.94% accuracy, but the more important result is the class-level asymmetry: glioma recall was 69.25%, with 97 of 123 missed gliomas predicted as meningioma. That finding is reported without concealment because it changes how the system should be described and used.

The engineering work demonstrates that genuine inference, genuine Grad-CAM, persistent patient/scan/report records, and self-contained reports can be combined in a reproducible academic prototype. The next steps are external validation, calibration and subgroup analysis, a targeted effort to improve glioma sensitivity, and the security and governance work required before any real clinical data is handled. Until those steps are complete, the correct framing is research prototype, not medical device.
